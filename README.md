# CrewHub

Корпоративна платформа для обліку змін, табелів і зарплати. Присутність на роботі
перевіряється не GPS, а IP-адресою робочого Wi-Fi.

- **Сервер:** Supabase (Postgres + RLS + Edge Functions + Realtime + pg_cron). Сюди
  надходять усі зміни, перерви, підключення та статистика; модератор бачить і редагує все,
  а кожне редагування пишеться в журнал аудиту.
- **Застосунок:** Flutter, один код для Android, iOS і веб-адмінки. Роль у профілі
  (`employee` / `moderator` / `admin`) визначає, що бачить користувач.

## Структура

```
supabase/
  migrations/
    20261018000001_core_schema.sql   таблиці: профілі, точки, Wi-Fi зони, графік, зміни, перерви,
                                     бонуси/штрафи, запити, журнали, сповіщення
    20261018000002_logic.sql         годинник зміни, контроль Wi-Fi, підрахунок годин і грошей,
                                     live-моніторинг, payroll, розгляд запитів, аудит
    20261018000003_security.sql      права доступу (RLS), realtime, pg_cron, сховище фото
  functions/clock/                   Edge Function: старт/стоп/перерви/пінг з перевіркою IP
  tests/                             сценарний тест SQL на звичайному Postgres
app/                                 Flutter-застосунок
```

## Як працює перевірка Wi-Fi

1. Телефон у Wi-Fi точки виходить в інтернет через **публічний IP роутера**. Для кожної точки
   потрібен статичний IP від провайдера (або підмережа, якщо провайдер видає блок адрес).
2. Адмін вносить цей IP у «Точки і Wi-Fi». Узнати його просто: підключитися до Wi-Fi точки і
   відкрити «Моя зміна», там показано IP, який бачить сервер.
3. Застосунок викликає Edge Function `clock`. Функція бере IP із заголовків запиту (клієнт не може
   його підставити) і викликає SQL-функцію, яка звіряє його з білим списком. SQL-функції годинника
   доступні лише серверу (service role), напряму з телефону їх не викликати.
4. Поки зміна відкрита, застосунок щохвилини шле пінг. Якщо пінгів з робочого IP немає довше
   за «Допустима втрата Wi-Fi» (за замовчуванням 5 хв), `sweep_stale_shifts()` (pg_cron, щохвилини)
   ставить зміну на неоплачувану паузу або закриває її, і шле сповіщення працівнику та модераторам.
   Повернувся в мережу — зміна продовжується сама.
5. Анти-фрод: якщо закрити зміну поза робочою мережею, вона закривається часом останнього
   підтвердженого пінгу, а не поточним часом. Кожна спроба (зокрема відмови) є в журналі підключень.

## Запуск

### 1. Supabase

1. Створіть проєкт на [supabase.com](https://supabase.com) (або локально `supabase start`).
2. Міграція сама вмикає **pg_cron** і ставить щохвилинну перевірку втрати Wi-Fi
   (перевірити: Integrations → Cron).
3. Застосуйте міграції: `supabase link --project-ref <ref>` і `supabase db push`
   (або вставте файли з `supabase/migrations` по черзі в SQL Editor).
4. Розгорніть функції: `supabase functions deploy clock admin-users` і
   `supabase functions deploy register --no-verify-jwt`.
5. Authentication → Sign In / Providers: вимкніть **Allow new users to sign up** і **Confirm email**.
   Реєстрація йде лише через функцію `register`, яка ставить акаунт на підтвердження.
6. Створіть першого користувача (Authentication → Add user) і зробіть його адміном у SQL Editor:
   ```sql
   update public.profiles set role = 'admin', phone = '0671234567' where email = 'you@company.com';
   ```
   Після цього він входить у застосунок номером телефону.
7. Працівники або реєструються самі (ім'я, номер, пароль) і чекають підтвердження в «Працівниках»,
   або їх додає адмін/модератор кнопкою «Працівник». Логін — номер телефону.

### 2. Flutter

```bash
cd app
flutter pub get
flutter run -d chrome \
  --dart-define=SUPABASE_URL=https://<ref>.supabase.co \
  --dart-define=SUPABASE_KEY=<publishable або anon key>
```

Для телефону — те саме з `-d android` / `-d ios`, для веб-адмінки — `flutter build web`.

### Тести

```bash
# SQL-логіка на чистому Postgres 15+ (імітує auth-схему Supabase)
DB_URL=postgres://postgres@localhost:5432/postgres ./supabase/tests/run_local.sh
# Flutter
cd app && flutter analyze && flutter test
```

|---|---|
| 1. Профіль і директорія | картка (фото, ПІБ, посада, відділ, точка, телефон, Telegram, ставка), стаж «В команді з травня 2025 (1 рік 5 міс.)», статуси й архів звільнених, директорія колег без ставок |

| 5. Адмінка | live-моніторинг (на точці, на перерві, втратив Wi-Fi, спізнюється) з Realtime, Wi-Fi зони, журнал підключень і журнал редагувань, payroll за місяць з експортом у CSV, правила компанії |

## Наступні кроки

- **Пуш-сповіщення.** Сповіщення вже створюються в таблиці `notifications`, а токени
  пристроїв зберігаються в `device_tokens`. Потрібно підключити Firebase (FCM) і функцію-відправник
  на вставку в `notifications`.
- **Пінг у фоні.** Зараз пінг іде, поки застосунок відкритий. Щоб він ішов при заблокованому
  екрані, на Android потрібен foreground service (наприклад, пакет `flutter_foreground_task`),
  на iOS фон обмежений системою, тож правильніше покладатися на допустимий інтервал втрати Wi-Fi.
- Завантаження фото з телефону в бакет `avatars` (бакет і права вже створені).
- Стрічка новин і чати (свідомо відкладено).
