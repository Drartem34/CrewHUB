# CrewHub

Облік змін, табелів і зарплати. Присутність на роботі перевіряється не GPS, а IP-адресою
робочого Wi-Fi: телефон працівника в мережі точки — зміна йде, вийшов з мережі — пауза.

- **Сервер** (`test_app/`): Python, Flask + SQLite, запускається одним `python start.py` на звичайному
  комп'ютері в локальній мережі. Уся логіка: зміни, перерви, контроль Wi-Fi, графік, дей-оффи й відпустки,
  бонуси/штрафи, зарплата, журнали підключень і редагувань, бекапи. Докладно — [test_app/README.md](test_app/README.md).
- **Android** (`android/`): легка обгортка над сайтом сервера (~30 КБ) з фоновою службою, що сама починає
  й закінчує зміну за робочим Wi-Fi. Підключення QR-кодом. Докладно — [android/README.md](android/README.md).
- **Документація**: `readme.html` — опис механізмів, ролей і FAQ.

## Швидкий старт

```bash
cd test_app
pip install -r requirements.txt      # Python 3.10+
python start.py                      # у Windows: двічі клікнути start.bat
```

Відкрийте адресу «Локальна мережа» з консолі (наприклад `http://192.168.1.23:5000`) на телефоні в тому ж Wi-Fi.
Перший вхід: `050 000 00 01` / `admin123` — система одразу попросить задати свій пароль.
Підмережа Wi-Fi цього комп'ютера додається як робоча при першому запуску; інші точки — у «Точки і Wi-Fi».

Служба Linux (старт з комп'ютером, перезапуск при збої): `./install_service.sh`.

## Як працює перевірка Wi-Fi

1. Сервер бачить IP, з якого прийшов запит. У локальній мережі це адреса телефона (192.168.x.x),
   тож робоча зона — підмережа Wi-Fi точки. Через інтернет-тунель — публічний IP роутера точки.
2. Підробити IP заголовком не можна: `X-Forwarded-For` приймається лише від власного тунелю, який сам його
   дописує (pinggy з `xff`), і береться остання адреса. Сам сервер (127.x) ніколи не «робоча мережа».
3. Поки зміна відкрита, телефон пінгує сервер. Тиша довша за допустиму — пауза, а після ліміту зміна
   закривається часом останнього підтвердженого пінгу. Час поза мережею не оплачується; поблажку за «сон»
   отримує лише застосунок (не браузер) і не довше 45 хв.
4. Закрити зміну поза мережею можна, але її кінцем стане останній пінг з точки. Кожна спроба (і відмова)
   пишеться в журнал підключень.

## Тести

```bash
cd test_app
python -m unittest test_crewhub test_hardening
```

`test_hardening.py` — тест на кожну виправлену дірку і баг, зокрема фаз-тест: сміття в кожну форму
від адміна й працівника не дає жодної помилки 500.

## Що далі

- **HTTPS у локальній мережі.** Зараз сервер працює по HTTP; застосунок звіряє `server_id` сервера, перш
  ніж віддати cookie входу, але трафік у Wi-Fi не шифрується. Повноцінний HTTPS потребує рішення щодо
  сертифіката (власний із закріпленням у застосунку чи справжній домен).
- **Пуш-сповіщення** на телефон (зараз сповіщення видно в застосунку й на сайті).
- Хмарна версія (Supabase + Flutter) обговорювалась як наступний крок, але в цьому репозиторії її немає.
