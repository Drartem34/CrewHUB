# Android-застосунок

Легкий застосунок (~300 КБ разом зі сканером QR, Android 6+), версія 2.1. Це вбудований браузер, що відкриває сайт сервера, плюс фонова
служба, яка сама починає й закінчує зміну за робочим Wi-Fi. Геолокація застосунку не потрібна:
перевірку Wi-Fi робить сервер за IP.

## Що вміє

- **Підключення QR-кодом** або коротким кодом з «Точки і Wi-Fi». Адреси сервера людина не бачить — лише назву
  компанії. Якщо в QR є Wi-Fi точки, застосунок пропонує під'єднатися до нього.
- **Перевірка сервера:** перш ніж віддати cookie входу, застосунок питає `/api/hello` і звіряє `server_id`.
  Інший пристрій з тією самою адресою в чужій мережі вхід не отримає.
- **Сервер змінив IP — пароль не потрібен.** Застосунок зберігає токен «запам'ятати мене» окремо, разом з
  `server_id` сервера, що його видав. Якщо за старою адресою тиша або чужий пристрій, застосунок сам шукає
  сервер у своїй підмережі (`/24`, той самий порт; лише якщо телефон у тій самій `/24`, що й стара адреса, —
  удома нічого не сканує), переходить на нову адресу і входить токеном. Те саме — після нового QR чи ручної
  адреси. Токен віддається лише серверу, що довів, що він справжній (див. нижче «Доказ сервера»).
  Пошук — не частіше раз на хвилину у вікні застосунку і раз на 10 хв у фоновій службі, ~3–6 с.
- **Фонова служба** (`WatchService`): сповіщення «CrewHub» у шторці, поки служба працює.
  - Стежить за Wi-Fi через системні події: щойно телефон вийшов з мережі, служба через мобільний інтернет
    повідомляє серверу точний час виходу (або з першим пінгом після повернення).
  - Поки зміна йде, Android будить службу будильником (у сні — раз на 5–15 хв). Процесор тримається
    увімкненим лише на час одного запиту — це береже батарею.
  - Поза зміною сервер підказує, коли наступна перевірка має сенс (`next_check`): телефон не будиться
    даремно вночі й на вихідних, а перед початком робочого часу чекає на автостарт.
  - Піднімається сама після перезавантаження телефона (`BootReceiver`).
- **Модель і назва телефона** для керівника: застосунок додає до запитів модель (`samsung SM-S911B`) і
  «Ім'я пристрою» з налаштувань телефона. Видно в картці працівника («Телефон людини») і в «Пристрої в мережі».
- Фото профілю з камери чи галереї, завантаження CSV, дзвінки й Telegram з картки колеги, кнопка «Назад».
- На слабкому телефоні сам вмикає легкий режим анімацій.

## Дозволи

| Дозвіл | Навіщо |
|---|---|
| Інтернет, стан мережі, стан Wi-Fi | зв'язок із сервером, події «підключився / вийшов з Wi-Fi» |
| Зміна Wi-Fi | під'єднатися до Wi-Fi точки з QR-коду |
| Камера | сканувати QR-код підключення |
| Фонова служба, будильник, wake lock, автозапуск | фонова перевірка зміни |
| Сповіщення | сповіщення служби й про зміни |
| Без обмежень батареї | застосунок попросить; без нього Android може «приспати» службу довше |

На телефонах Xiaomi, Huawei, Samsung варто ще вручну дозволити автозапуск і «без обмежень» у налаштуваннях
батареї для CrewHub — інакше система може вбивати фонові служби.

## Збірка APK

Без Android Studio й Gradle, на Linux (Ubuntu/Debian):

```bash
sudo apt install aapt apksigner zipalign dalvik-exchange openjdk-17-jdk
cd android
ANDROID_JAR=шлях/до/android.jar ./build.sh      # android.jar API 34 (Android SDK platforms/android-34
                                                 # або android-all з Maven Central, див. коментар у build.sh)
cp build/CrewHub.apk ../test_app/static/CrewHub.apk   # тоді його роздає сервер: посилання на сторінці входу
```

### Ключ підпису — секрет

- При першій збірці `build.sh` створює `crewhub.keystore` і `keystore.pass` (випадковий пароль).
  Їх **немає в репозиторії** (`.gitignore`). Зробіть резервну копію обох файлів у надійному місці.
- Оновлення ставиться поверх встановленого застосунку **лише з тим самим ключем**. Загубили ключ — людям
  доведеться видалити застосунок і поставити новий.
- Свій ключ: `CREWHUB_KEYSTORE=шлях CREWHUB_KS_PASS=пароль ./build.sh` (або `CREWHUB_KS_PASS_FILE`).
- Старий тестовий ключ (пароль `crewhub123`) був опублікований разом із кодом до версії 16, тому замінений.
  Застосунок, підписаний ним, видаліть з телефона один раз і встановіть новий.

## Демо-застосунок (без сервера)

`CrewHub_Demo.apk` — окремий застосунок «CrewHub Демо» (пакет `ua.crewhub.demo`, ставиться поруч з робочим).
Показати систему клієнту чи новому працівнику без сервера й без мережі.

- Усередині — знімки всіх сторінок з тестовими даними: вхід, 8 екранів працівника, 25 екранів керування
  (огляд з «Пристроями в мережі», працівники й картка кожного, запити, графік тиждень і місяць, точки, журнали,
  зарплата, правила).
- На вході — кнопки тестових акаунтів: «Адмін» і «Модератор» відкривають керування, «Іван» і «Ольга» — кабінет працівника.
- **Зміну можна почати, взяти перерву й закрити** — вона рахується на телефоні. Клітинки місячного графіка
  перемикаються. Форми нічого не зберігають: з'являється підказка «Це демо».
- Інший місяць, CSV, завантаження в демо недоступні (підказка замість переходу).
- Справжніх даних з вашої бази в демо немає: знімки робляться з окремої тимчасової бази.

Збірка (те саме оточення, що для основного застосунку, плюс Python з Flask):

```bash
cd android
ANDROID_JAR=… ./build.sh                 # спершу основний: створить ключ підпису
ANDROID_JAR=… ./demo/build.sh            # → demo/build/CrewHub_Demo.apk
cp build/CrewHub.apk demo/build/CrewHub_Demo.apk ../test_app/static/   # сервер роздає їх за /app і /app/demo
```

`demo/build_demo.py` відкриває сторінки сервера від імені Івана й адміна і складає їх у `demo/assets/www`;
`demo/demo.js` підміняє запити до сервера; `demo/src/…/DemoActivity.java` віддає файли за адресою
`https://demo.crewhub/` прямо з APK. Перезбирайте демо після змін інтерфейсу — інакше в ньому лишиться старий вигляд.

## Код

| Файл | Що робить |
|---|---|
| `MainActivity.java` | головне вікно (WebView): екран підключення, QR/код, підтвердження `crewhub://connect`, перевірка `server_id`, Wi-Fi з QR, вибір фото, завантаження файлів |
| `WatchService.java` | фонова служба: події Wi-Fi, пінги `/api/clock/auto`, звіт про вихід `/api/clock/left`, будильники, сповіщення |
| `ScanActivity.java` | сканер QR (бібліотека ZXing у `libs/`) |
| `BootReceiver.java` | запуск служби після перезавантаження |
| `res/` | іконка, тема |

Що застосунок шле серверу:
- `User-Agent` з `CrewHubApp/2.1`, `CrewHubDevice/<випадковий id>` (за ним сервер упізнає «свій» телефон),
  `CrewHubModel/…`, `CrewHubName/…` (URL-кодовано), `CrewHubLite` на слабкому телефоні;
- у пінгах — `unrestricted` (чи дозволено працювати без обмежень батареї) і `away_since` (коли вийшов з Wi-Fi);
- сторінки сайту в застосунку, як і в браузері, шлють відбиток пристрою (`fp`, див. [08-security.md](08-security.md#відбиток-пристрою-і-mac)).

### Доказ сервера

`server_id` не секрет (він у QR), тож лише за ним віддавати токен входу не можна. Застосунок надсилає випадкове
`n` і `s` — selector свого токена (без секретної частини). Сервер відповідає
`proof = HMAC-SHA256(ключ = sha256(validator) hex, повідомлення = "n:server_id")`. Хеш `sha256(validator)`
лежить лише в базі справжнього сервера, а застосунок рахує його з власного токена. Збіглось — це той самий
сервер: застосунок кладе `crewhub_remember` у cookie нової адреси (`CookieManager.setCookie`) і відкриває сайт.
Код: `WatchService.proven`, `discover`, `moveServer`, `rememberFrom`, `keepRemember`; у вікні — `verifyThenLoad`.
Налаштування застосунку: `remember` (токен), `remember_sid` (id сервера, що його видав); стираються, коли
сервер показав сторінку входу (вийшли, змінили пароль, «Вийти на всіх»).

Перевірити, що Java-код компілюється, без повної збірки:
`javac --release 8 -cp android.jar:libs/zxing-core-3.5.3.jar` з заглушкою `R` (див. `build.sh`).
