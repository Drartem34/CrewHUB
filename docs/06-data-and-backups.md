# Дані, резервні копії, відновлення

## Де лежать дані

Усе, що створює робота сервера, лежить у **папці даних**, окремо від програми:

- Linux / macOS: `~/CrewHub-data` (домашня папка користувача, від якого запущено сервер);
- Windows: `C:\Users\<ім'я>\CrewHub-data`;
- інше місце — змінна `CREWHUB_DATA` (наприклад, другий диск).

Точний шлях показано в консолі при запуску («Папка даних») і в адмінці: «Правила» → «Де лежать дані».

```
CrewHub-data/
├── crewhub.db            база SQLite (+ crewhub.db-wal, crewhub.db-shm під час роботи — не чіпайте)
├── settings.ini          правила, точки, Wi-Fi, мережі, порт — текстом (див. 04-settings.md)
├── server_id.txt         постійний ідентифікатор сервера (за ним застосунок упізнає «свій» сервер)
├── people/               особові папки працівників
│   └── Іван Петренко/
│       ├── profile.json   профіль (ім'я, телефон, посада, контакти можна правити руками)
│       ├── картка.txt     те саме людською мовою + години й заробіток за місяць
│       ├── shifts.csv     усі зміни таблицею (Excel)
│       ├── shifts.json, requests.json, adjustments.json, schedule.json   повні дані для відновлення
│       └── avatar.jpg     фото
├── backups/
│   ├── crewhub_2026-10-24_090000.zip    щоденні копії (останні 30)
│   ├── manual/                          копії з кнопки «Завантажити зараз» (останні 3)
│   └── видалені/                        папки людей, видалених в адмінці
├── logs/crewhub.log      журнал сервера (5 файлів по 1 МБ, старі витісняються)
└── oui.txt               (необов'язково) база виробників за MAC для «Пристрої в мережі»
```

Папка програми (`test_app/`) містить лише код. Її можна видалити й розпакувати нову версію — дані не постраждають.

### Перехід зі старої версії

До версії 17 база лежала в `test_app/crewhub_test.db`, а `people/` і `backups/` — поруч. Перший запуск
нової версії:

1. копіює базу в папку даних цілою (разом з незлитим журналом WAL) і перевіряє копію;
2. переносить `people/`, `backups/`, `server_id.txt`;
3. перейменовує стару базу на `crewhub_test.db.перенесено-<дата>` (страховка; через тиждень можна видалити);
4. кладе в `test_app/` файл `ДЕ_ДАНІ.txt` з новим шляхом.

Якщо копія не пройшла перевірку, стара база лишається на місці, а сервер пише про це в консолі й журналі.

## База — єдине джерело правди

Усі дані живуть у `crewhub.db`. Особові папки й `settings.ini` — це «дзеркала» для людини й страховка:

- **Особові папки** (`people/`) переписуються фоном за кілька секунд після будь-якої зміни в базі
  (лише змінені файли).
  - Поправили в `profile.json` ім'я, телефон, посаду, відділ, контакти чи дату прийому — зміни потрапляють
    у базу. **Роль, статус і ставку файлом не змінити** (це робить адмін в адмінці, з записом у журнал).
    Неприйняту правку сервер відкочує і пише причину в `ПОМИЛКА.txt` у цій папці.
  - Видалили папку чи від'єднався диск — акаунт **не** видаляється, папка відтворюється з бази.
  - Перейменували папку — сервер упізнає людину за телефоном.
  - Нова чи повернута з бекапу папка **не** створює акаунт сама. Створити з неї акаунт — лише вручну на сервері:
    ```bash
    cd test_app
    python profiles.py list              # які папки підключені
    python profiles.py import "Ім'я"     # створити акаунт з папки (із змінами, запитами, бонусами)
    python profiles.py import-all        # усі ще не підключені
    ```
    Пароля в папці немає: після імпорту скиньте людині пароль в адмінці.
  - Видалити людину можна лише в адмінці. Її папка переїжджає в `backups/видалені/`.
- **settings.ini** — див. [04-settings.md](04-settings.md#файл-settingsini).
- **Аватарки** зберігаються в базі; `avatar.jpg` у папці — копія.

## Резервні копії

- **Автоматично:** раз на добу (перша — одразу при запуску, якщо сьогоднішньої ще немає). Копія — один zip: база (цілісний знімок, навіть
  під час роботи) + усі особові папки. Зберігаються останні 30 (`CREWHUB_BACKUP_KEEP`).
- **Вручну:** «Правила» → «Резервні копії» → «Завантажити зараз» — zip завантажиться в браузер і ляже
  в `backups/manual/` (останні 3; щоденні не витісняє).
- **Друга копія:** «Правила» → «Друга копія» — папка на іншому диску, флешці чи в синхронізованій теці
  Google Диска/OneDrive. Кожна щоденна копія ляже і туди. Якщо друга папка недоступна, у «Правилах» буде
  попередження, а основна копія однаково робиться.
- Раз на добу сервер ще й прибирає старий журнал підключень (старші за 180 днів) і прочитані сповіщення
  (старші за 60 днів) і стискає журнал бази (WAL). Зміни й зарплата не видаляються ніколи.

Порада для «Nokia 3310»-надійності: друга копія на інший фізичний диск + раз на місяць «Завантажити зараз»
на свій ноутбук.

## Відновлення

### База пошкодилась (вимкнули світло, збій диска)

Нічого робити не треба. При запуску сервер перевіряє базу; пошкоджену відкладає вбік
(`crewhub.db.broken-<дата>`) і відновлює з найсвіжішої **справної** копії (пошкоджені копії пропускає).
Людей і їхні зміни, свіжіші за копію, підтягує з особових папок, а правила й точки — з `settings.ini`.
У консолі й журналі буде повідомлення, що сталося.

### Відновити з конкретної копії вручну

1. Зупиніть сервер.
2. Розпакуйте потрібний `crewhub_<дата>.zip`: у ньому `crewhub.db` і папка `people/`.
3. Замініть `crewhub.db` у папці даних (і видаліть `crewhub.db-wal`, `crewhub.db-shm`, якщо є).
   За потреби — замініть і `people/`.
4. Запустіть сервер.

### Перенести сервер на інший комп'ютер

1. Зупиніть сервер на старому.
2. Скопіюйте всю папку `CrewHub-data` у домашню папку на новому (або куди вкаже `CREWHUB_DATA`).
3. Розпакуйте програму, запустіть.

Телефони знайдуть новий сервер, якщо в нього та сама адреса в мережі. Інакше покажіть працівникам новий QR
з «Точки і Wi-Fi»: застосунок упізнає «свій» сервер за `server_id`, тому скопіюйте й `server_id.txt` (він уже в папці).

## Забули пароль адміністратора

На самому сервері (доступ до комп'ютера = доступ до системи):

```bash
cd test_app
python recover_admin.py            # вибрати адміна й задати новий пароль
python recover_admin.py admin      # одразу для конкретного адміна (логін, як у списку)
```

Пароль вводиться приховано, при першому вході система попросить змінити його. Усі попередні входи цього адміна
на інших пристроях скасовуються, дія пишеться в журнал.

## Журнал сервера

`<папка даних>/logs/crewhub.log` — помилки запитів, фонових потоків (контроль Wi-Fi, бекап, особові папки,
settings.ini, пошук пристроїв) і запуску. Якщо фоновий потік падає чи замовк, адмін бачить червоний банер,
а `/health` відповідає кодом 503 (можна підключити зовнішній моніторинг).
