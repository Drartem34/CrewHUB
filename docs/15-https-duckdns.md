# 15. Шифрування (HTTPS) безкоштовно: DuckDNS + Let's Encrypt (версія 17.18)

CrewHub у локальній мережі працює по HTTP. Wi-Fi шифрує повітря, але хто знає пароль від Wi-Fi (будь-який колега),
теоретично може перехопити, що телефон надсилає серверу, — зокрема пароль при вході. HTTPS це закриває: браузер і
сервер для кожного з'єднання домовляються про свій ключ, якого немає ні в коді сайту, ні в мережі. Прочитати чи
підмінити дані не можна.

Щоб браузер довіряв серверу без жодних попереджень і налаштувань на телефонах, серверу потрібен справжній
сертифікат. Його безкоштовно видає **Let's Encrypt**, але лише на назву, а не на адресу `192.168.0.9`. Назву
безкоштовно дає **DuckDNS**. Усе інше CrewHub робить сам:

- каже DuckDNS свою адресу в локальній мережі (і при кожній її зміні) — назва в робочому Wi-Fi веде прямо на сервер;
- отримує сертифікат у Let's Encrypt і продовжує його сам (Let's Encrypt дає на 90 днів; продовжуємо, коли лишилось
  менше 30). Доводить, що назва його, записом у DuckDNS — серверу не треба бути доступним з інтернету;
- відкриває вхід `https://назва.duckdns.org` поруч зі звичайним `http://IP:5000`;
- сторінка, відкрита по http, сама переходить на https, якщо він з цього телефона відкривається.

Через DuckDNS дані CrewHub не йдуть: він лише підказує телефону адресу сервера у вашій мережі.

Потрібні: **інтернет на сервері** і бібліотеки `cryptography` та `cheroot` (вони в `requirements.txt` — `start.sh` /
`start.bat` поставлять їх самі при наступному запуску з інтернетом).

## Налаштування (один раз, 3 хвилини)

1. **duckdns.org** → увійти (Google, GitHub…) → у полі **sub domain** придумайте назву, напр. `crewhub` → **add domain**.
   Поле **current ip** можна не чіпати — CrewHub сам впише туди адресу сервера.
2. Угорі сторінки DuckDNS — **token**. Це секрет: нікому не пересилайте і не показуйте на скріншотах (якщо показали —
   на duckdns.org можна зробити новий).
3. CrewHub → «Правила» → «Дисципліна і доступ» → блок **«Шифрування (HTTPS)»**: галочка, назва (`crewhub`), токен →
   «Зберегти правила». За 1–2 хвилини там з'явиться «Працює: https://crewhub.duckdns.org · сертифікат до …». Ще не
   з'явилось — «Перевірити зараз» і оновіть сторінку; якщо щось не так, там буде причина.
4. Закріпіть за сервером адресу в робочому роутері («резервування адреси» / DHCP reservation), щоб вона не стрибала.

Порт: типово 443 (тоді адреса без номера порту). Якщо 443 зайнятий іншою програмою чи немає прав (Linux не від
root), сервер сам візьме 5443: адреса буде `https://crewhub.duckdns.org:5443`. Брандмауер Windows спитає дозволу
для Python — дозвольте для приватних мереж.

Токен не потрапляє ні в `settings.ini`, ні в «Журнал редагувань» (там лише «токен змінено»), а лежить у базі. Можна
задати його змінною середовища `CREWHUB_DUCKDNS_TOKEN` — вона важливіша. Сертифікат і ключ — у папці даних, `tls/`.

## Як це бачать люди

Нічого не встановлюють. Відкривають CrewHub як завжди — сторінка сама перейде на `https://crewhub.duckdns.org`
(у рядку адреси — замочок). Один раз доведеться увійти з паролем ще раз: для браузера https-адреса — новий сайт.
Телефон свій сервер упізнає сам (за MAC і відбитком), прив'язка «Телефон людини» лишається.

Застосунок Android поки ходить по http, як раніше; перехід застосунку на https — наступним кроком.

## Якщо щось не так

| Що бачите в «Правилах» | Причина |
|---|---|
| «немає бібліотек cryptography і cheroot» | сервер запущено не через `start.sh` / `start.bat` (вони ставлять бібліотеки самі) чи без інтернету. Поставте вручну: `test_app/.venv/bin/python -m pip install cryptography cheroot` (якщо є `.venv`), інакше через систему — Fedora `sudo dnf install python3-cryptography python3-cheroot`, Arch `sudo pacman -S python-cryptography python-cheroot`, Ubuntu `sudo apt install python3-cryptography python3-cheroot`, Windows `python -m pip install cryptography cheroot`. Потім перезапустіть сервер |
| «Працює», але з телефона не відкривається | брандмауер не пускає порт: `start.sh` відкриває 5443 сам (firewalld, ufw); вручну — `sudo firewall-cmd --permanent --add-port=5443/tcp && sudo firewall-cmd --reload` чи `sudo ufw allow 5443/tcp`; Windows спитає дозволу для Python — «Дозволити» |
| «DuckDNS не прийняв назву чи токен» | токен чи назва з помилкою; на duckdns.org перевірте, що назва ваша, і вставте токен заново |
| «немає зв'язку з DuckDNS / Let's Encrypt» | на сервері немає інтернету; сервер спробує знову за годину |
| «Let's Encrypt не підтвердив назву» | запис у DuckDNS не встиг розійтися — «Перевірити зараз» за кілька хвилин |
| «порт 443 зайнятий… працює на 5443» | усе працює, просто з номером порту в адресі |

Сторінка не переходить на https, хоча в «Правилах» «Працює»: роутер не пускає назву, що веде на внутрішню адресу
(«захист від DNS rebinding» — є в частини роутерів). У налаштуваннях роутера вимкніть цей захист для
`duckdns.org` (чи загалом). Поки не вимкнете — усе працює по http, як раніше.
