# 12. HTTPS у локальній мережі через Caddy (необов'язково)

CrewHub у локальній мережі працює по HTTP, і цього достатньо, щоб усе працювало. HTTPS через проксі Caddy додає:

- **шифрування між телефоном і сервером усередині Wi-Fi** — колега, який знає пароль від Wi-Fi, не підгляне
  чужий пароль від CrewHub;
- **можливості браузера, які працюють лише на https** — напр., заряд батареї в Chrome (на http сторінка
  його не бачить, і сервер не знає, що телефон розряджається).

Caddy стає перед сервером: браузер → `https://IP-сервера` (Caddy, порт 443) → `http://127.0.0.1:5000` (CrewHub).
Сам CrewHub не змінюється і далі слухає порт 5000, тож застосунок і старі закладки працюють як раніше.

## Що треба знати заздалегідь (4 пастки)

1. **Сервер має бачити справжній IP телефона.** За проксі всі запити приходять ніби з 127.0.0.1 — для CrewHub
   це «не робоча мережа», MAC телефона не визначається, автозміна не працює. Тому CrewHub запускають з
   `CREWHUB_TRUST_PROXY=1`: тоді сервер бере IP телефона із заголовка `X-Forwarded-For`, який дописує Caddy
   (і лише для з'єднань з цього ж комп'ютера — телефон підробити свій IP так не може).
2. **Телефони не довіряють сертифікату Caddy, поки його не встановити.** Для IP-адреси Caddy видає сертифікат
   своїм власним локальним центром сертифікації. Сервер йому довіряє (`caddy trust`), а телефони — ні:
   браузер покаже «Підключення не захищене», доки на кожен телефон не встановити кореневий сертифікат Caddy
   (`root.crt`, див. крок «Телефони» нижче). Кореневий сертифікат діє 10 років; проміжні Caddy оновлює сам.
3. **Застосунок CrewHub лишається на `http://IP:5000`.** Android-застосунок довіряє лише системним сертифікатам,
   а не встановленим вручну, тож на `https://` локального Caddy він не відкриється. Нічого робити не треба:
   застосунок і далі ходить на порт 5000 напряму. HTTPS — для тих, хто відмічається в браузері.
4. **Для браузера `https://…` — новий сайт.** Окреме сховище браузера: новий код пристрою (`web-…`) і новий вхід
   «запам'ятати мене». Людям треба один раз увійти з паролем. Сервер сам упізнає той самий телефон за MAC і
   відбитком і перенесе на новий код прив'язку «Телефон людини». Якщо ні — «Перезаписати код пристрою» в
   картці працівника (код людина бачить у «Налаштуваннях додатку»).

Порада: закріпіть за сервером постійний IP у роутері (резервування DHCP). Адреса стоїть у Caddyfile, і якщо
роутер дасть серверу інший IP, HTTPS перестане відкриватись.

## Windows

1. Завантажте Caddy для Windows (amd64) з <https://caddyserver.com/download> і покладіть `caddy.exe` у папку,
   напр. `C:\Caddy`.
2. Поруч створіть файл `Caddyfile` (без розширення). Замість `192.168.1.50` — IP сервера в робочому Wi-Fi
   (його видно в консолі CrewHub: «Сервер працює: http://…»):

   ```
   https://192.168.1.50 {
   	tls internal
   	reverse_proxy 127.0.0.1:5000
   }
   ```
   Порт `5000` — порт CrewHub (`port` у settings.ini чи `CREWHUB_PORT`).
3. У `test_app\start.bat` перед рядком `:loop` додайте рядок `set CREWHUB_TRUST_PROXY=1` і перезапустіть CrewHub.
4. Відкрийте командний рядок **від імені адміністратора** в `C:\Caddy` і запустіть `caddy run`. Перший запуск
   створить локальний центр сертифікації і попросить дозволу додати його в довірені Windows — погодьтесь.
   Брандмауер Windows спитає про доступ до мережі — дозвольте для приватних мереж (порт 443).
5. Перевірка: на сервері відкрийте `https://192.168.1.50` — має відкритись сторінка входу без попереджень.
6. Щоб Caddy вмикався сам: «Планувальник завдань» → «Створити завдання» → тригер «Під час запуску» → дія
   `C:\Caddy\caddy.exe` з аргументами `run --config C:\Caddy\Caddyfile`, «Виконувати незалежно від входу
   користувача» і «З найвищими правами» (як автозапуск CrewHub у [01-install.md](01-install.md#автозапуск-разом-з-компютером)).

Кореневий сертифікат для телефонів: `%AppData%\Caddy\pki\authorities\local\root.crt` (того користувача, від
якого запускали Caddy).

## Linux (напр. Arch)

1. `sudo pacman -S caddy` (Debian/Ubuntu — за інструкцією на caddyserver.com).
2. Відредагуйте `/etc/caddy/Caddyfile` (його читає служба caddy) — той самий вміст, що вище для Windows.
3. `sudo systemctl enable --now caddy`, потім `sudo caddy trust` — додати кореневий сертифікат Caddy в довірені
   цього комп'ютера (команда бере його в запущеної служби).
4. CrewHub з `CREWHUB_TRUST_PROXY=1`:
   - служба (`install_service.sh`): `sudo systemctl edit crewhub` → вписати
     ```
     [Service]
     Environment=CREWHUB_TRUST_PROXY=1
     ```
     і `sudo systemctl restart crewhub`;
   - запуск вручну: `CREWHUB_TRUST_PROXY=1 ./start.sh`.

Кореневий сертифікат для телефонів: `/var/lib/caddy/.local/share/caddy/pki/authorities/local/root.crt`
(служба caddy) або `~/.local/share/caddy/pki/authorities/local/root.crt` (якщо запускали `caddy run` самі).

## Телефони: встановити кореневий сертифікат

Перешліть `root.crt` на телефон (пошта, месенджер, USB). Це робиться один раз на кожному телефоні.

- **Android:** Налаштування → Безпека (чи «Безпека й конфіденційність») → «Шифрування та облікові дані» →
  «Встановити сертифікат» → «Сертифікат ЦС» → вибрати `root.crt`. Назви пунктів трохи різняться в різних
  виробників; пошук у налаштуваннях за словом «сертифікат» знаходить потрібне.
- **iPhone:** відкрити `root.crt` (через AirDrop чи Пошту) → Параметри → «Профіль завантажено» → «Встановити».
  Потім Параметри → Загальні → Про пристрій → «Довіра сертифікатам» → увімкнути для «Caddy Local Authority».

Після цього `https://192.168.1.50` відкривається на телефоні без попереджень.

## Якщо щось не так

| Що бачите | Причина |
|---|---|
| Через https усі «не в робочій мережі», автозміна не працює | CrewHub запущено без `CREWHUB_TRUST_PROXY=1` |
| «Підключення не захищене» на телефоні | на телефон не встановлено `root.crt` Caddy (або на iPhone не ввімкнено довіру) |
| https не відкривається зовсім | змінився IP сервера (оновіть Caddyfile або закріпіть IP у роутері); брандмауер закрив порт 443; Caddy не запущено |
| «Перевірка безпеки не пройдена» при відправці форм | у Caddyfile змінено заголовок `Host` — залиште `reverse_proxy` без додаткових налаштувань |
| Застосунок не відкривається на `https://…` | так і має бути — застосунку лишайте `http://IP:5000` (пастка 3) |
